Softball Lineup Manager

Plan inning-by-inning lineups for a youth softball team. Track your roster, set position priorities, build batting orders, and let the app suggest a fair, rule-respecting field for every inning. Data syncs across all your signed-in devices.

Getting Started — Seasons & Teams

The app organizes everything by Season → Team → Game. Use the dropdowns at the top of every page to switch between active Season and Team. The Manage Seasons and Manage Teams buttons (top-right of the nav) let you create, rename, or delete them.

  • A Season is a container (e.g. "Spring 2025"). Multiple teams can live in one season.
  • A Team has its own roster and its own list of games.
  • Switching season/team in the header changes what shows up on every page below.

Roster Page

The Roster page lists every player on the active team as a card with their info and position priorities.

Adding and editing players

  • Click + Add Player in the toolbar (or the dashed card at the end of the grid) to add someone new. Name is required; jersey and primary position are optional.
  • The ✏️ Edit button on each card opens the same form for name, jersey, primary position, and full priority grid.
  • Use the search box at the top to filter by name, jersey, or primary position.
  • Export CSV downloads the full roster as a spreadsheet.

Position priorities

Each card shows nine field positions. The color and label tell you how well a player fits each one:

  • Best — top fit for that position (priority 1).
  • Good — capable backup (priority 2).
  • Can — can play if needed (priority 3).
  • — — no priority set; auto-populate will only put them there as a last resort.

Click any position cell to cycle through: nothing → Best → Good → Can → nothing. Changes save immediately.

Lineup Page

This is where you build the lineup for a specific game. The page splits into a left sidebar (Games, Present, Batting Order) and a main crosstab grid (positions × innings).

Left sidebar

  • Games — every game for this team. Click one to switch; the grid updates. The + button creates a new game (carrying over the present-players list and batting order from the currently-selected game).
  • Present — checkbox for every player on the roster. Check = playing today, uncheck = sitting out. The Add sub… input adds a temporary player marked as a Sub, visible only in this game.
  • Batting Order — numbered list of present players. Use the ▲ ▼ arrows to reorder.
  • Each section scrolls independently, so a long games list won't crowd Present or Batting.

Game info strip (top of the main panel)

  • Edit the game's name, date, opponent, and location inline.
  • 📊 Excel downloads a spreadsheet of the lineup (positions across the top, innings down the side, batting order below).
  • 🗑 Delete removes the game.

The crosstab grid

Two views are available, switched by the By Position / By Player toggle in the top toolbar:

  • By Position (default) — positions as columns, innings as rows. The interactive grid where you drag chips to assign players.
  • By Player — players as columns, innings as rows. Each cell shows the position that player is in for that inning. Drag a cell onto another player in the same inning row to swap their positions; the same rules (no consecutive bench, etc.) apply.

In the default By Position view, the grid has columns for each position — 9 field slots (P · C · 1B · 2B · 3B · SS · LF · CF · RF) and 5 bench slots (B1 – B5) — and one row per inning. Each inning row contains:

  • A navy strip on the left with the inning number and a per-inning ⚡ Auto button.
  • A Pool row above the slots, showing players who haven't been assigned anywhere yet in that inning.
  • The actual slot row — 14 drop targets aligned to the column headers.

To assign a player: drag a chip from the pool into a slot, or drag from one slot to another. The chip's colored dot shows their priority for that position. Each chip has a × button to clear the slot. Drag is scoped to a single inning — you can't drop across inning rows.

Auto-populate

  • ⚡⚡ Auto All Innings (top toolbar) fills every inning at once based on the active rules.
  • ⚡ Auto on a specific inning refills just that one.
  • Auto-populate respects whichever rules are checked in the Rules panel — disable them to change the algorithm's behavior.

Rules Applied

The Rules Applied panel sits below the inning grid. Each rule has a checkbox — uncheck to turn it off. A disabled rule stops affecting auto-populate, drag-drop enforcement, and validation messages. Rule states sync to the cloud, so toggling on one device propagates to others on next refresh.

1
No consecutive bench
A player can't be on the bench two innings in a row. Enforced when you drop a chip onto a bench slot; the drop is rejected with a brief warning.
2
Fair bench distribution
Everyone should bench once before anyone benches twice. Auto-populate gives players with fewer prior benches a stronger preference for the field; if the rule is broken, a "Bench imbalance" message appears in the validation bar.
3
Position priorities considered
Auto-populate scores every player–position pairing by the priority you set on the Roster page: 1 = 100, 2 = 60, 3 = 30, no priority = 5. Higher scores win the slot.
4
Only fill empty slots
Auto-populate leaves every already-filled position alone — field, bench, pitcher, catcher — and only assigns players to slots that are currently empty. To rebuild an inning from scratch, clear chips with their × button first, or turn this rule off.
5
Infield, pitcher, or catcher in the first 4 innings
Every present player must end up in pitcher, catcher, 1B, 2B, 3B, or shortstop in at least one of the first four innings. Auto-populate boosts placing players who haven't had an early infield slot yet.

Validation Bar

The yellow strip above the inning grid lists the most pressing issues to fix:

  • Players who are checked-in present but not assigned anywhere in a given inning.
  • Empty field positions when some players have already been placed.
  • Active rule violations: consecutive bench, bench imbalance, missing early infield.

The Rules Applied panel below the grid is the long-form view; the validation bar at the top is the quick-glance "what needs fixing right now."

Data, Sync, and Export

  • All your data is stored in a single JSON file in Cloudflare R2, gated by Cloudflare Access (email allowlist). Edits sync across every signed-in device.
  • The colored dot in the top-right header shows save status: ● saved, ● saving, ● error, ● offline.
  • ⬇ Export JSON downloads your entire dataset (seasons, teams, rosters, games, rules) as a backup.
  • ⬆ Import restores from a JSON file, replacing whatever is currently in the cloud.
  • 🖨 Print formats just the active lineup grid for printing — sidebars and toolbars are hidden.
